# 方法库（程序法）——已验证有效的思维程序

与盲区库互为表里：盲区是"怎么错"，方法是"怎么对"。
每条方法必须链接本仓库实例；无效的方法按交租规则裁撤。

---

### M-001 先测量后重写
注入约束或不达标时，第一动作是测量缺口，不是选方案。
缺口大小决定响应档次：11% 的缺口与 10 倍的缺口，合法响应完全不同。
**实例**：D-012——p99 注入后先测（1.7µs / 11.1µs），再裁决 D-009 去留。

### M-002 三分法：测量 / 阈值 / 目的
测量是事实（与阈值无关的分布）；阈值是决策（合法性来自下游锚点）；
目的是锚点的来源。红灯说"代码≠决策"，不说"代码坏"——
故红灯后有三条合法响应：改代码 / 带锚点改决策 / 撤回无锚点阈值。
**实例**：实验 B 的 10µs 道具阈值质询，G-003 标注 synthetic。

### M-003 追问成命题（品味开采）
把"感觉不对"经苏格拉底对话变成可检验命题：命题成熟为检查器的迁入硬区，
不成熟的留在软区带签名。默会知识不是账本的对立面，是它的燃料。
**实例**：O-006"总 FIFO"→ 单消费者保序（不可检验→可检验）；
"阈值须有锚点"从一次质询变成 G-003 字段。

### M-004 生成义务而非枚举问题
不列"写代码要考虑什么"的清单；编码"什么决定自动生成什么义务"的触发器。
触发器库是过去问题的化石，每次账本没预见到的问题回写一条。
**实例**：triggers/ 四类十条；O-024 的 p99 义务由 G-003 v1 注入自动逼出。

### M-005 有条件反事实
一切"如果改用 X"的结论都以当前前提为条件。前提（如阈值）被撤回，
整个 invalidated 集合蒸发。反事实输出必须携带其依赖的前提。
**实例**：实验 C 的 invalidated 集以 p99 预算成立为条件；D-013 第一问先问前提。

### M-006 最小可运行 + 交租
新机制从最小闭环起步（3 本账 + 1 纪律 + 1 触发器库），
每个 artifact 必须约束生成、拦截错误、或被删除。全有或全无永远无法起步。
**实例**：Spec Ledger 一周内从元模型讨论落成可运行系统；LLM 无锚点理由被拒。

### M-007 分层互证
同一系统用不同档位的独立证据：语言强制（竞争自由）→ 测试（行为）→
模型检查（协议/活性）→ 证明（顺序核心）。各档弱点互补，单档失效不塌方。
**实例**：O-011/O-016/O-021 三档覆盖同一队列的不同侧面；Verus 核心证明
在并发策略更换反事实下原样存活（正交性被实验 C 预测）。

### M-008 判例法生长
每次真实事故/争论后回写：命名 → 检测 → 对策 → 实例（本库的扩展协议）。
与触发器回写同构：一个是代码层的学习，一个是推理层的学习。
**实例**：本库全部 12 条判例来自 2026-10-03 至 10-05 的真实工作。

### M-009 校准记账（预测在先，结果在后）
对未来可判定事项记录预测与置信度，事后对分——命中率反馈闭环修正过度自信。
预测与结果的间隔必须足够长以排除"先知道答案再补预测"。
**实例**：实验 B 注入时预测 invalidated 集并在事后对照；
实验 C 自审 1.0 分反衬"预测先于结果"纪律的必要。

### M-010 异体对照
把同一判断交给不同主体（人/另一模型/另一会话）独立得出，再比对分歧。
分歧处即铰链实体——最值得人裁决的位置。同体复核（自审）不产生新信息。
**实例**：实验 C 的 agent 分类 vs 金标准流程；AI 两个会话对同一设计的独立裁决。

### M-011 跨档同名（桥的燃料）
同一概念在 TLA⁺ 动作、Rust 函数、Verus 契约之间使用同一动词命名
（push/pop/close/wake），无法同名的（如 PSend↔push）在 ledger/bridge.yaml
语义点表显式登记映射。名字是最低成本的对账抓手——同名即天然可机械核对，
异名必须人工登记一次，之后同样可机械核对。注意词汇分工：桥表的 concept 列
是**语义锚**（人类可读的语义），rationale 的 anchor 是**出处指针**——
两个词表条目（thinking/glossary.md），不得混用。
**实例**：bridge.yaml SP-01..08——core.rs 的 push/pop 与 queue.tla 的
PSend/CPop 异名映射，concept 列即语义锚。
**判例**（2026-10-07 体检）：bridge.yaml 曾把本条错引为 M-009（校准记账）——
编号漂移在跨档引用上的第一次实弹命中；勘误入 D-022。 prose 引用库条目无
lint 把关，候选硬化：MD 内 M-xxx/BS-xxx 引用在界检查。

### M-012 载体法则（载体跟随验证关系）
文档的承载格式由其**验证关系**决定，不由偏好决定：
- 机器要查的 → schema 文本（YAML，配 lint）——可 diff、可审计、AI 可直读；
- 派生视图 → 生成器 + 缓存文件 + `--check` 漂移红灯（LEDGER.md 模式：载体是生成器，渲染物是缓存）；
- 人 + AI 共读的活文档 → Markdown；
- 冻结的历史文本 → 原样保留，收编不转写；需要编辑时先转 md（带 diff 校验）再改；
- 可执行的验证 → 代码（语言跟随验证器：.tla 归 TLC，verus 属性归 Verus）。
数据库/二进制不配当**载体**，只配当**工具**——除非 (a) 多写者并发、
(b) 查询超出平面文件扫描能力；迁移触发器登记为监测项，不预先决定（G6 处置：展出+监测）。
**实例**：账本 YAML + thinking MD + 手册 HTML 冻结收编 + LEDGER.md 生成模式——
系统自发演化出此分工，本条为追认命名（2026-10-07，tmp 原件删除、仓库版单源化时确立）。
