# 盲区库（判例法）——工程推理的已知失败模式

与触发器库的关系：触发器库管**代码层**的"什么决定生成什么义务"；
本库管**推理层**的"思考过程怎么错"。元一层。

生长协议（判例法）：每次真实的错误推理/争论/事故之后回写一条——
**命名 → 谬误形式 → 检测信号 → 对策 → 本仓库实例**。
交租规则：每条判例必须链接至少一个本仓库实例或一条结构化对策；
两者皆无的条目是散文，禁止入册（中间地带非法原则对元认知同样适用）。

对策分两档：能硬化的升为结构防线（lint 字段、流程规则、账本 schema）；
不能硬化的留在评审清单，供 AI 与人做决策/评审时对照。

---

### BS-001 无锚点阈值（阈值篡夺目的）
- **形式**：为可测维度设定无下游依据的硬数值，再用它否定/通过工作。两个变体：
  否定合格品（p50=1.7µs 的实现被 10µs 道具阈值判死）；**阻止真实改进被看见**
  （新代码客观更好但未达标，改进本身被无视）。
- **别名**：McNamara 谬误 / Goodhart（指标取代目标）/ 虚假精确
- **检测信号**：从阈值到目的的推导链断裂——"为什么是 10µs 而不是 15µs？"答不上来
- **对策**：预算类条目强制 derived_from 锚点，无锚点标 synthetic（已硬化进 G-003 v1）；
  评审变更时**分开记录相对改进（delta）与绝对达标（阈值）**——红灯后三选一：
  改代码 / 带锚点改决策 / 撤回无锚点预算
- **实例**：实验 B——10µs 道具阈值，险些否定合格实现并触发不必要的全量重写

### BS-002 重写偏好（缺口大小失明）
- **形式**：不达标时默认"全部重写"，忽视缺口幅度与修复成本之比
- **检测信号**：方案比较里没有"缺口大小 × 失效集代价"这一项
- **对策**：先测量缺口（D-012 模式），方案按（修复成本 × 失效集）排序后再裁决
- **实例**：实验 B——p99 仅超标 11%，本能反应却是 lock-free 全量重写
  （会兑现实验 C 预测的整个 invalidated 集）；自旋混合可能 1/10 成本修复

### BS-003 理性链虚构（Parnas 陷阱）
- **形式**：把事后重构的"完美设计过程"当作真实过程，掩盖回溯与推翻
- **检测信号**：一份没有 superseded / invalidated / 精化历史的"完美"文档
- **对策**：账本原生记录修订链（superseded_by、证据升级历史）
- **实例**：O-006"总 FIFO"不可检验，被精化为单消费者保序形式——真实过程就是回溯的

### BS-004 抽象上飘（元模型上瘾）
- **形式**：每轮讨论加新名词、新框架、新公式，落地物为零
- **检测信号**：N 轮之后，可运行/可检查的东西数量不变
- **对策**：交租检验 + "第一铲土"纪律——框架的价值由它催生的下一个工件度量
- **实例**：早期设计讨论连续七轮"下一步再抽象"，直到被中断并强制实验

### BS-005 工具囤积
- **形式**：因"工具可能有用"而引入，而非"有义务饿着等它"
- **检测信号**：说不出哪个义务的哪个证据档位需要它
- **对策**：工具采购必须指向一个具体的、证据档位不足的义务
- **实例**：Lean 被否（无 C/C++/Rust 自动验证器，无饿着的义务）；
  TLA+ 被采纳（O-016/O-017 恰好饿着 liveness 证据）

### BS-006 账本演出（先射箭后画靶）
- **形式**：AI 为既有意图补写体面的决策理由，账本沦为小说
- **检测信号**：rationale 无机器可查锚点；反事实提问时分类失准
- **对策**：rationale 锚点强制（TOSEM 实证：LLM 生成理由 F1 仅 0.35）+ 定期反事实审计（实验 C）
- **实例**：实验 C 的存在动机本身；金标准由人独立标注

### BS-007 平均品味冒充裁决
- **形式**：把 LLM 的统计品味（训练语料均值 + 账本约束）当作利益相关者的判断
- **检测信号**：一个价值判断找不到承担后果的签名者
- **对策**：软声明签名规则——签名的重量来自签名人承担后果
- **实例**：宪法三律之二；G 账本与 D 裁决权保留给人

### BS-008 场景逃逸（数字有，场景没）
- **形式**：预算/断言给出数值却不钉死测量场景，导致不可比、不可复现
- **检测信号**：数值条目回答不了"在什么负载/容量/对手方行为下测的？"
- **对策**：数值必须与场景定义绑定（写进 checker 本体）；规约必须完整刻画结果
- **实例**：bench_p99 把竞争场景写进测试本体；Verus 证明两次踩"规约不完备"坑
  （new 缺 cap 等式、push/pop 缺 cap 保持——调用链知识断链）

### BS-009 单次证据冒充分布
- **形式**：一次测试通过即宣称性质成立，忽视执行路径覆盖率
- **检测信号**：证据档位与义务风险不匹配（高危义务只有单跑测试）
- **对策**：检查器阶梯——证据强度按风险升级（压力/性质测试 → 模型检查 → 证明）
- **实例**：C++ 压力测试初版漏掉按引用捕获的数据竞争——"恰好一次"断言恰好拦住；
  义务 O-003 的升级优先级因此上调

### BS-010 验证器信任转移
- **形式**：信任 TLA+/Verus 的结论，忘记它们验证的是模型/核心而非全部
- **检测信号**：说不出"这个证明没有覆盖什么"；模型↔代码桥无抽查记录
- **对策**：分层互证（各档覆盖面互补）+ 桥的机械对账。**已硬化（D-016）**：
  ledger/bridge.yaml 语义点映射表 + tools/bridge_check.py（B1 常量登记 /
  B2 被检性质必须有人认领 / B3 语义点符号三向存在），红灯档位与 lint 同级；
  桥表 verus: null 行诚实登记未覆盖面（关闭/唤醒时序）
- **实例**：D-006 接受时明确写下边界——TLA+ 查协议不查代码，一致性靠评审+快照；
  D-016 起升级为机械检查器，O-025 为其证据义务

### BS-011 幻觉 / 无锚断言（AI 与人同构）
- **形式**：以流畅的"记忆"或"推理感"替代证据。虚构不存在的 API、凭印象报版本号、
  为既有结论补造依据。AI 的"幻觉"与人的"想当然"在账本抽象层是同一类：无锚断言
- **检测信号**：任何"我记得/应该是"级别的声明，在入账前没有运行过或查证过
- **对策**：宪法三律对世界层声明同样适用——锚点（来源链接/运行输出）、检查器
  （编译/运行即查证）、签名（人验收）
- **实例**：TLA+ `Bag` 算子——AI 自信使用了不存在的标准算子，解包 jar 读源码才证伪；
  verus 发布资产名凭印象三连 404，最终从 expanded_assets 页面取证

### BS-012 自审不可见偏差
- **形式**：同一推理者复核自己——系统性偏差对复核者不可见，自洽≠正确
- **检测信号**：审计者与被审计者是同一个主体（或同一个模型）
- **对策**：异体对照——人工金标准、换模型对照、双人互审（double crux）。**已硬化（D-027）**：
  义务 schema 增必填字段 `bs_guard`／`bs_note`——每条不变量级检查器**必须登记它防的是哪条判例**
  （或写明不针对任何已编目判例的理由），由 `tools/ledger_lint.py` 在 error 档强制；
  引用须真实存在于本文件。外部独立收敛的实例见 `thinking/CANDIDATES.md` §一
- **实例**：实验 C 自审基线 47/47=1.0——满分恰恰是警告：它只度量了自洽性；
  results.md 的诚实性声明第一条即为本判例

### BS-013 证据时点性（pass 会腐烂）
- **形式**：把"验证时点的 pass"当成"持续成立的 pass"。证据只证明当时那一刻；
  之后世界继续动——账本变了、代码重编译了、工具换机了、生成物落后于输入了——
  而 pass 静默保持
- **检测信号**：证据没有复跑命令；或复跑命令在本机环境根本不可执行
  （路径形态不兼容、构建产物 hash 钉死、硬编码机器路径）；生成物与输入无 --check 门
- **实例**（2026-10-07 体检，三连命中）：O-029"零漂移"证据 pass 与 LEDGER.md
  实际漂移并存入库（digest --check 红灯，而 O-029 的 pass 是验证时点的快照）；
  ledger_check 复跑档因 config 存 bash 形态路径、经 cmd.exe 调用必然
  path not found——"可复跑"从未真正成立；O-023 命令钉死构建 hash，重编译即失效。
  肇事者包括审计者本人（M-012 提交未重跑 digest）
- **对策**：**已硬化（D-021/D-023）**——pre-commit 四合一门含 digest --check
  （生成物新鲜度入提交门，tools/gate.py）；evidence 必须 command+notes 可复跑，
  ledger_check 经 config 路径单点真正可执行（O-033）；义务生命周期字段
  （superseded_by/frozen）让历史证据显式退场，不再冒充活跃 pass
