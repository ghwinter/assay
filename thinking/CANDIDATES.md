# 元认知候选池（判例法挖矿 v1，未激活）

**本文件是候选池，不是元认知库。** `thinking/blind_spots.md` 与 `thinking/methods.md` 是判例法层；
本池按 `ledger/triggers/CANDIDATES.md` 的同构角色设立：**激活任一条需走 D 裁决**
（追加进盲区库/方法库并过其交租规则）。在裁决之前，本池条目**不构成规范**，
不得被下游引用为结论（AGENTS.md「AI 产出一律证据待验」）。

**来源与写法**：来自对若干成熟系统的**定向代码阅读**——读的是规律，不是项目。
因此本池**不记录项目身份，也不记录外部路径**，实例一律**按机制描述**；
完整出处（仓库、文件、行号、取得时点）留在提出方的读数记录里，本池只登记
**核验状态**。理由见 §四 BS-C2：外部实例在本仓没有合法锚点形态（D-022 的 anchor 存在性
lint 只查本仓路径），所以"按机制描述 + 出处留存下游"是它当前唯一自洽的写法。

**每条按 AGENTS.md「新形态先举例」给出实例与反例**——只给实例不给反例的条目，
按该纪律视同过早公理化，禁止升库。

**与触发器池的分工**：触发器池管**代码层**（什么决定生成什么义务）；本池管**推理层**
（思考过程怎么错、怎么对）。

## 一、候选判例（盲区库）

### BS-C1 空作用域通过（vacuous pass）

- **形式**：检查器的被检集合由**可能为空的过滤条件**决定，于是它检查了**零个**对象却报告通过。
  与 BS-009（单次证据冒充分布）的区别：BS-009 是**样本太少**，本条是**样本恰好为零**且无人察觉。
- **两个独立实例**（外部，按机制描述，核验状态：已核）：
  1. 一个技能元数据校验器，其扫描集合限定为"含某产品专用元数据文件的技能目录"，
     而该元数据文件恰好被同目录的忽略规则排除——于是**在干净检出上它什么都不查**，
     打印"0 项策略对齐"并退出 0。**空集合不是错误路径，是它的正常路径。**
  2. 一次手工度量：统计某文件里"以快照键命名的字段数"，朴素文本匹配命中 **31**，
     而锚定到字段声明后真值为 **16**——差额来自**该文件自己的文档段落里写着那十六个键名**。
     **检查把自己的说明书也数了进去。**
- **检测信号**：
  - 检查器**不报告它检查了多少对象**；
  - 被检集合由 glob / 过滤器 / 平台条件决定，且在被检对象不存在时**静默为空**；
  - 通过文案里出现 `0`（"0 项对齐""0 个问题"）而退出码为 0。
- **对策（可硬化）**：检查器必须打印 `N checked`，且 **`N == 0` 即失败**。
  硬化形态与 BS-001 的 `derived_from` 同构——把"作用域非空"变成**必填/必打印量**，而不是纪律。
- **反例（本条边界，必须先说）**：`N checked` 只挡得住"零"，**挡不住"全是空壳"**——
  一个检查了 200 个空文件的检查器照样通过。故本条对策是**必要条件而非充分条件**；
  与之互补的独立对策见 §三「空强制产物」。
- **交租**：对策可硬化，按盲区库抬头的两档规则，**以"一条结构化对策"交租**。

### 对 BS-013 的**对策增量**提案

现有硬化（D-021/D-023）管两件事：生成物 `--check`、证据命令可复跑。二者都预设
**载体是可复跑的、且知道自己的新鲜度**。而 **shallow clone / 未提交工作树 / 编译期内联的
快照**三者**没有这个前提**：载体不会自称过期，版本历史也正常给出那 1 个提交。

拟增两条检测信号与一条对策：

- **检测信号（新）**：被引用的外部载体**没有记录来源身份**（来源标识 / 取得方式 / 取得时点 / 核验状态）；
- **检测信号（新）**：把"**是否存在**"与"内容是什么"混为一谈——前者更便宜且更常出事
  （一次存在性查询即可判定"已不在"，而**不需要读它**）；
- **对策（可硬化）**：引用外部载体时，**存在性与时点必须分开记录**：取得方式 + 来源标识 + 时点
  + "是否仍在远端 HEAD"的核验结果；核验失败**不得静默降级为"已核"**。

### BS-C2 外部实例无家可归（交租规则的边界）

- **形式**：判例法库的**交租规则**要求条目链接"至少一个**本仓库实例**或一条结构化对策"；
  方法库更严，明写"**必须链接本仓库实例**"。当一条规律来自**外部系统**（症状与对策都清楚，
  在本仓尚无实例）时，它**没有合法的入册形态**，只能留在提出方仓库当散文——
  而宪法第 16 行恰好禁止这类"既不机器检查、又无签名的约束性散文"。
- **实例（本池自身）**：本池全部条目的实例栏都是外部实例；**anchor 存在性 lint（D-022）只查
  本仓路径**，所以这些实例既不能作为 anchor，也不能作为本仓实例交租。
- **检测信号**：一条规律被反复引用、反复重述，但账本里查不到它——它在下游仓库的文档里。
- **对策**：三选一，需裁决——
  (a) 允许"**外部实例**"入册，形态为 来源标识 + 取得方式 + 取得时点 + 核验状态
      （与 BS-013 增量同构）；
  (b) 保持严格，但为外部规律设**明确的暂存区**（本池即是），并要求**升库前必须在本仓落地一个实例**；
  (c) 要求每条外部规律**先转写成一条触发器候选**（代码层的可机械检查形式），
      由下游项目落地后回填实例。

## 二、候选方法（方法库）

方法库现行交租规则为"必须链接本仓库实例"，下列四条**目前只有外部实例**，
故先入本池；裁决时须按 BS-C2 的 (a)/(b)/(c) 之一处理。

### M-C1 存活仪器（churn / 年龄）

按路径取提交历史，得到 **改动次数 / 首次出现 / 最后改动**——可在**不取任何对象**的前提下完成
（远端按路径查询提交接口，比加深副本便宜得多）。

- **实例**：一个 132 行的文件在 **5 年 10 次**改动；一个 1159 行的核心文件在 **2.75 年 51 次**。
  两者都是各自系统里最定型的代码。
- **反例**：**浅副本会让本方法返回"从不改变"这一看起来像结论的假信号**
  （实测：四个副本全部报"1 个提交"）。故本方法**必须先过镜头新鲜度检查**（M-C4），
  且**比值必须同时报分子与分母，分母 < 10 时只报计数**（实测：一个 1/2 的比值是噪声）。

### M-C2 提交分类（区分"它在动"与"它在被磨"）

只看改动次数会得出错误结论。对每条提交问一句：

| 类 | 判据 | 含义 |
|---|---|---|
| ① 自身设计变了 | 提交在改**该文件的职责**（重命名职责、拆合、搬迁） | 结构**未定** |
| ② 硬化，接口不变 | 性能 / 安全 / 可测性，对外行为不变 | 结构已定，**在被磨** |
| ③ 上下文税 | 改动来自文件之外：编译器升级、lint 清理、依赖签名变更、他处改名 | **文件本身没问题——是它所在的世界动了** |
| ④ 上了维护、没接上 | 有提交，但**没有任何门禁调用它** | churn ≠ 重要 |

- **实例**：某文件建好后 9 条提交里 **8 条是上下文税**，只有 1 条是它自己的性能修复——
  **"为什么它不变"的答案不是"它简单"，是"第一次就对了"**。
  同系统另一个核心文件 51 条提交**全是②**，没有一条是重新设计。
- **反例**：提交信息不可信时本方法失效（压缩合并、`wip`、由模型生成的提交信息）。
  它只在提交历史干净、且合并策略未压平的情况下有效。

### M-C3 沉积标记普查（在冻结快照上替代 churn）

数两类标记：**流动**（`TODO|FIXME|HACK|XXX|legacy|transitional|deprecated|workaround`）与
**定型**（`must|never|always|the only|single source of truth|invariant`）。

- **实例**：比值最低的两处（**0.04 / 0.10**）正是各自系统**最底层、最不动的机制**，
  而它们的文本里满是"必须/永不/唯一"。**结论：定型的代码不是没话说，是每一条不显然的决定
  都配了一句"什么绝不允许发生"。**
- **反例**：**它数的是散文，不是行为**——系统可以一边写"唯一的写入路径"一边有三条。
  它只说明**作者在辩护什么**，必须配一次结构核对（数实际的写入点）。
  且它**区分不了"因为对而定型"与"因为年轻而定型"**：一个年龄很短、但作者很能写不变量散文的仓库，
  在本方法下会读成"已经定型"。

### M-C4 阅读前的两问（镜头新鲜度）

任何跨系统阅读之前：① **副本的时点**是什么；② **准备引用的文件在远端 HEAD 上还在吗**
（用存在性接口查询即可，**判定"已不在"不需要读它**）。

- **实例**：一次阅读的本地副本为某日，被引文件在**次日**的提交里被整个删除；
  引用文本仍以"该系统的机制"陈述它。**浅副本不会自称过期。**
- **反例**：无网络的机器上第 ② 问问不了。此时必须**标注"未核"**，不得默认为"在"
  （AGENTS.md「未知标注」：陈述未知时标"未知"，不得以流畅文本填充）。

## 三、配套的结构性对策（可硬化，独立于上列判例）

### 空强制产物：强制项允许为空，就会生产出成百个空产物

- **实例（按机制描述，核验状态：已核）**：某系统曾要求**每一个**工作区包都发布一个伴生入口，
  包括根本没有可检查关系的包。结果是**两百余个带说明的空入口**，每个都带着源文件、公共导出、
  发布项、仅供该机制使用的依赖、类型引用、构建接线与注册测试。其归档说明的判词是：
  **"这套机制只表达否定结论，没有增加运行时断言。"** 其后的修法是双管——
  要求清单文件**记录该单元省略的理由**，并**拒绝空实现**。
- **对策（可硬化）**：一条"每个 X 都必须有 Y"的规则，若 Y 允许为空，**必须同时给出**
  ①"没有 Y"的**书面理由字段**，②一个**读得到该理由**的检查器，③**拒绝空实现**。
- **与 BS-C1 的关系**：BS-C1 挡"零个对象"，本条挡"零内容的对象"；两者互补，缺一即留缺口。

- **形式**：检查器的设计者在**未知会盲区库**的情况下工作，把一个已被编目的盲区
  当作新问题重新犯了一遍（实例见 §一 BS-012 行）。
- **对策（可硬化）**：新增**不变量级**检查器时，账本强制一个字段声明"它防的是哪条判例"，
  或**说明为什么不防任何一条**。形态与"要求写明省略理由否则拒收"的既有先例同构，
  也与 BS-013 的硬化方式（加 schema 字段 + lint）同构。
- **反例**：强制字段会让每一条琐碎检查都带一句理由，产生噪音。
  边界是：**只对不变量级检查器强制**（O 账里 checker 类型为 lint / manual / proof 的义务），
  单元测试不强制。
