## 实验 A：生成质量对比

- 触发：在本仓库实现一个真实新功能（候选：timed_pop / 广播扇出 / 优先级变体，届时选定）。
- 对照组：全新 agent 会话，无账本提示，直接实现。
- 实验组：按 AGENTS.md 纪律走完整账本流程。
- 可选扩展：C++ 归档实现（pilot/，D-008）可作跨语言对照材料。
- 主指标：评审发现的缺陷数、测试失败数、需求遗漏数、人工纠偏次数。

## 实验 B：决策推翻（核心实验）

- 注入约束：把 G-003 预算收紧为「p99 < 10µs @ 4 线程」
  （预期推翻 D-009 的 mutex+condvar 选择——阈值低于 condvar 唤醒成本的合理区间）。
- 流程：同一 agent 在账本在场时响应变更；变更经 D-009 supersession 走账。
- 主指标：
  1. time-to-green——从注入到 ledger-lint 全绿且测试全过的人 + agent 小时数；
  2. 人工介入点数；
  3. 失效决策召回率——未被告知的情况下，找出全部受累及 D/O/artifacts 的比例。

## 实验 C：反事实审计（兼账本诚实度审计）

- 提问：「若 D-009 改为 lock-free ring，哪些决策/义务/证据仍成立？」
- 要求输出五分类：still-valid / invalidated / newly-required / unaffected / unknown。
- 对照人工金标准，计算 precision / recall。
- 附加用途：定期执行，抓取"先射箭后画靶"的 D 草稿
  （AI 为既有意图补写体面理由的作弊），账本自身的 mutation test。

## 实验 D：检查器变异测试（SG9 钝化的主动重放，D-024 预登记 2026-10-07）

- 方法：对实现做人工变异（`<=`→`<`、删去 close 检查、调换返回序等），逐变异运行
  其义务的检查器；检查器未变红即登记"钝化 checker"。
- 主指标：变异杀死率（killed / total）；未杀死者回写义务升级（检查器换档）或判例。
- 频率：引擎项目每个垂直切完成后一轮；首跑对象 qcore.rs（O-013/O-014/O-028 义务族）。
- 与实验 C 的关系：C 测账本诚实度（先射箭后画靶），D 测检查器效力（守门人睡着了）。
  两者合起来才是"审计者由谁审计"的完整答案。
