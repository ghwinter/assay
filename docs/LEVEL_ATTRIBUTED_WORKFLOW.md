# 分层归因工作流（提案 v0）

> **本文是什么**：一份**提案**，不是规范。它不修改 `PROTOCOL.md`、`CONSTITUTION.md`、`AGENTS.md`
> 或引擎行为。其中任何一条若要激活，须按本仓规则走一次 `D` 裁决，并各自交出一次真实摩擦。
> **本文不是什么**：不是新工具清单，不是路线图承诺，不是对操作系统、编程语言或编译器的重新定义。
> **强度标注**（沿用 `docs/paper/` 的纪律）：**[P]** 有证明支撑；**[A]** 在写明的前提下成立；
> **[H]** 可证伪假设；**[X]** 本文的推断，尚无仓内实例。

## 0. 一句话

论文里唯一还没有文件形态的形式对象是**层**。
而论文自己已经给出了它的表格（`appB` 模板一）和它的可行性判词

所以缺的不是分析器，是**一份声明格式加一条 lint**。本文给出该格式、随附的四条合取规则、

层、无视集、假设封闭、归因、读集——**没有一条落在这条横线上**。

### 1.2 两处可当场指认的空洞 **[X]**

1. `assumption_ids` 是引擎里的 `Vec<String>`（`engine/src/main.rs:92`），会被写进证据信封

## 2. 四条合取规则

四条都是**静态**的、**有限结构**上的判定，按 §3.1 的顺序表属于第 1 档
（`structural`：对有限结构穷举）——**范围是 `unbounded`，成本是文本 join**。
论文的 `pr:level-real` 说"写不出第五项的层不是层"；这里把它写成会红的东西。

### R1 层现实判据 **[A]**（`pr:level-real`，`appB` 模板一填表要求 1）

> 每一层必须有非空的「可以无视什么」。空 = 红灯。

来源是论文原话："'可以无视'一列不得留空。留空意味着这一层不是层。"

### R2 归因与语言一致 **[A]**（`def:obligation-assign`，`appB` 模板一填表要求 3，`pr:level-language`）

> 每条不变式必须写明它归哪一档保证（mechanical / monitoring / consensus），
> 且该档的**观测域必须能表达这条不变式**。

`ch08` Table `tab:assurance-matrix` 就是这张对照表。此规则拦住的是论文称为
"读码中最严重的错误"的那类：用指针分析去回答"这笔交易是否被允许"。
它**只在出现矛盾时报红**（声明的观测域 vs 声明的不变式），**不在缺失时报红**——
缺失由 R1 与 `def:obligation-assign` 的三分类接管。

### R3 假设必须被兑现或被认领 **[A]**（`prop:operad-compose`，`rmk:feedback`）

> 纵向：第 k 层「假设下一层提供什么」⊆ 第 k−1 层「保证什么」∪ 已登记且写明承担者的外部假设。
> 横向：复合体内「u 的保证被 v 的假设引用」这张有向图必须无环；
> 有环 ⇒ 该复合体**必须附一份不动点论证**（存在性与唯一性），否则其组合论证作废。

这是全篇最值得机械化的命题：它是**图性质**，因此 `structural` 档就能判，
而论文说这比有界模型检查更强（§3.1"范围看的是覆盖面，不是工具的名字"）。
`rmk:feedback` 给了它变更触发的牙齿：**引入反馈不是局部改动**——
retry、cache 回写、双向同步、事件循环，任何把无环接口图变成有环的编辑，
都作废既有组合论证，与各组件是否仍各自正确无关。

### R4 判定词由 (capability, scope) 导出 **[A]**（成功判据 S4，`pr:three-states`）

> 判定不是从退出码导出，而是从 (能力, 强度, 范围) 导出；
> 有界/采样检查能给出的最高诚实判定是"**未观察到违反（范围=…）**"，
> 永远不得印成"φ 成立"。

## 3. 声明格式：一张表 + 两个字段

### 3.1 层表 `levels/Λ.toml`（直接照抄 `appB` 模板一的列）

```toml
[[level]]
id     = "L1"                     # 层的稳定标识
name   = "基础设施与运行时"
role   = "infrastructure"         # 见 §3.2 的六职能归属
participants = ["allocator", "scheduler", "event-loop"]

# 保证什么：**只放声明 ID**，句子留在清单里（散文只写一次）
guarantees = ["C-010", "C-011"]

# 假设下一层提供什么：同样只放 ID 或已登记的外部假设
assumes_of_below = ["C-002"]      # 或 ["EXT-durability-flush-policy"]
external_assumptions = [          # 无法由下一层兑现者，必须写明承担者
  { id = "EXT-flush-policy", text = "…", owner = "human:<role>",
    refuted_by = "…", ref = "…" },
]

# 可以无视什么（R1：必填）
may_ignore = ["SQL 语义", "查询计划形状", "上层的事务边界"]

# 每条不变式归哪一档保证，以及该档的观测域（R2：必填）
[[level.assurance]]
claim    = "C-010"
mode     = "mechanical"           # mechanical | monitoring | consensus
observer = "type-system"          # 判定该命题的观测域，用于 R2 一致性
```

### 3.2 六职能的承载者（`th:six` + `cor:buildadopt`）

`th:six` 的结论是六职能**不能被省略**，只能**自建或采纳**。于是层表应在 L1 行上逐格回答：

```toml
[level.k6]
identity_lifecycle      = { bearer = "adopted:host" }
allocation_reclamation  = { bearer = "adopted:host" }
scheduling              = { bearer = "built:local-executor" }
naming_addressing       = { bearer = "adopted:host" }
communication_sync      = { bearer = "built:channel" }
fault_isolation_recovery = { bearer = "adopted:kernel-capability" }
```

**六格全填 = 该层的算子语义自洽；缺格 = 那一格的不变式一定散落在别处。**
`appA` A.2 的第二条收益给了这条规则牙齿：缺基座不只是更贵，
它**强制不变式散落，从而永久抬高全系统的读集下界**。
所以本规则与 T4 是同一个测量的两个视角。

### 3.3 模块契约的两个字段（`appB` 模板二）

模板二 18 个字段中，有三个是机器可读的合取点，其余是散文：

- `Oblivious set`（模板二把它加粗并标 "required"）→ 对应 R1；
- `Leak-pair risk`（第 17 项，"接口相同而外部行为不同的已知场景"）→ **探针生成器的输入**；
- `Identity` 里的 "the level it belongs to" → 对应 R2。

## 4. 十个仪器（分三档，各自写明买它的摩擦）

每条按 `ch09` `pr:demote` 的四步登记：**可观察后果 / 会否证它的观察 / 最小实验 / 对照条件**。

分档依据是**论文自己写到了哪一步**：

| 档 | 判据 | 仪器 |
|---|---|---|
| **A 论文已写出算法** | 算法在论文里，机械，只需一个仓 | T8 粗粒化执行器、T1 层表 lint、T4 读集、T9 单调性 lint |
| **B 需要生成器或 schema 变更** | 判定原则已在论文里，缺的是载体 | T2 接口图、T3 泄漏探针、T5 观测秩、T7 产物绑定、R4 失败类别 |
| **C 涉组织，回答论文的开放问题** | 论文自己列为未解 | T6 佐证与 `q`、T10 运输前提 |

### T8 `assay coarse` — 粗粒化执行器 **（`pr:coarsegrain-impl` 4.20、`def:coarsegrain` 4.18、`conj:relevant` 4.19 / H10）**

**论文把算法写完了**："从模块依赖图出发，反复施加三个操作：(i) 合并 fan-in 与 fan-out 低于阈值的节点；
(ii) 收缩传递依赖边；(iii) 抹掉不携带任何不变式的节点（`S(ι)=∅`）。每一步记录存活结构的变化。
整个实验只需要一个仓库和一张依赖图，**不需要标签，也不需要人工分类**。"

- 可观察后果：随粒度变粗，**存活集**的成员及其变化序列。
- 会否证它：存活集里出现六职能之外的结构，或某一职能在中等粒度就被冲掉（H10 的否证条件）。
- 最小实验：本仓 + `cargo metadata` 的依赖图，跑一遍，看存活集是否收敛到 `[level.k6]` 的六格。
- 对照：把阈值做敏感性分析（论文自己点名这是"任意参数"）。
- 服务：H10、`conj:relevant`、以及 `ch03` 的收敛论题——
  **这是全篇唯一一个能在单个项目内否证收敛论的实验**，不需要跨项目统计比较。
- **注意**：论文没给阈值取值，也没定义"仍然可辨认"。这两处空白必须在实现时显式登记为
  `trust_assumption`，否则本仪器会假装自己是无参数的。

### T9 `assay monotone` — 单调性 lint **（`rmk:calm` 4.13）**

> "对'协调'类函数有一条更锐利的、**可以静态检查**的判据：该计算是否单调。
> 非单调性（唯一性约束、否定、阈值聚合、非交换更新）逼迫某个位置承担协调。"

- 可观察后果：代码中被标记为"必须协调"的位点，以及触发它们的非单调构造数。
- 会否证它：被它判为需要协调的位点，在去掉该构造后**仍然**需要协调（说明判据抓错了东西）。
- 最小实验：对 `pilot-rs` 与 `engine` 各跑一次，人工核对两个位点。
- 对照：一个纯单调子系统应当**不变红**（否则它对一切代码都红，等于不红）。
- 服务：`rmk:calm`、`th:integration` 里的 `k`——论文说"对单调子系统，`k` 可以降到近乎常数"，
  所以本仪器同时是 `n·m > c(nk+m)+F` 里 `k` 的一个估计器。
- 价值：它把"规模到了就该统一"换成"**非单调性一出现就该统一**"，
  也就是把建基座的触发条件从规模改成结构，**这比等规模化更早、更便宜**。

### T1 `assay level` — 层表 lint **（R1、R2）**

- 可观察后果：层表里 `may_ignore` 为空、或 `assurance.observer` 与 `claim` 不相容的条目数。
- 会否证它：一个项目在接入前后，**同一批属性被漏掉的机械保证数量不下降**。
- 最小实验：指标本仓自己的 `levels/Λ.toml`，跑一次，看它是否对 `C-001`/`C-002` 报出
  "`observer = 手写词表` 无法表达 `text = 协议不点名任何后端`"——**这是一条真实的 R2 矛盾**，
  本仓已有（`assay/manifest.toml:30` 的 `trust_assumption` 正是作者对此的自认）。
- 对照：同一份层表交给第二个人独立标注，比对一致率（**这就是论文的开放问题 O7**）。
- 服务：O7、H5。

### T2 `assay compose` — 接口图与无环性 **（R3）**

- 可观察后果：接口图的环数；`assumes_of_below` 中未被兑现的 ID 数。
- 会否证它：在被判定"无环"的复合体上，注入一次 retry（`rmk:feedback` 点名的四类编辑之一），
  检查**没有**转红。若转不红，本仪器是装饰。
- 最小实验：在 `examples/` 里取一个真实纵切，手工补出 ID 边，跑一次；再注入 retry。
- 对照：同一编辑注入到一条**本来就有环**的复合体上，应当**不变红**（否则它是"凡变更即红"）。
- 服务：`prop:operad-compose`、`cor:three-failures`。

> **这条仪器最重要的输出不是红灯，是一条饿着的义务。** 环出现时它产出的不是"失败"，
> 而是一张**良定性义务**（该反馈环的存在性与唯一性）。这正是 TLA+ 与 Lean 的**合法入口**（见 §5）。

### T3 `assay leak` — 泄漏探针 **（`prop:leakpair`、`cor:diagnose`、H6）**

- 可观察后果：自动生成的"接口相同、内部状态或外部环境不同"的执行对中，外部行为发散的比例。
- 会否证它：生成的对**无法有效触发泄漏**，或发现率与人工边界质量评分无关（H6 的否证条件）。
- 最小实验：取 `pilot-rs` 的队列边界，把 `bridge.yaml` 里 `verus: null` 的两处
  （`SP-04` 关闭在 shell 层、`SP-06` 关闭唤醒全部阻塞者）各展开成一对待比较的执行。
- 对照：对同一模块的**内部**函数做同款对拍，应当**发散**（说明探针确实在测泄漏，不是在测等价）。
- 服务：H6。

> 论文原话："工程上'影子状态'、'隐式全局'、'跨请求缓存污染'都是泄漏对的具体实例。"
> 这些恰是单元测试逃逸率最高的缺陷类别，而 `differential` 能力**已经在 §3 表里**——
> 需要新造的只是**生成器**，协议一个字不用改。

### T4 `assay readset` — 读集与治理复杂度 **（`def:readset`、`th:centralise`、H4）**

- 可观察后果：`Q = E[|ρ(c)|]`（按变化分布加权）、它的规模标度指数、
  以及**声明读集**（`[[change]] touches` + `inputs`）与**经验读集**（Git 共同变更）的差。
- 会否证它：标度指数相对幅度与传统规模指标**没有增量预测力**（H4 的否证条件）。
- 最小实验：本仓有 32 条 `D`、47 条 `O`、本清单 2 条 `[[change]]` 与完整提交史——
  **数据已经在仓里，不需要新采集**。先算声明读集与经验读集的散布图。
- 对照：对同一时段算"按文件数计"的传统指标，比较两者对返工的解释力。
- 服务：H4、`cor:buildadopt`、`def:governable`。
- **诚实边界**：`def:governable` 的 `C(t)=E[ρ]·λ` 与 `K=hb` 里，只有 `E[ρ]` 与 `λ` 可从仓里算；
  `h`（人头）与 `b`（带宽）必须由组织声明。**本文不声称它是自动仪表盘**（论文反对意见五已就 `D=ℓ−ℓ*` 承认同类问题）。

### T5 `assay rank` — 观测秩与监视器可表达性 **（`prop:observability`、`rmk:monitor-limit`）**

- 可观察后果：被指派给某判定器的每条性质，是否落在该判定器**声明的观测域**之内；
  落在其外的性质数。
- 会否证它：被它判为"秩不足"的性质，在**增加采样/加跑次数**后确实被发现了。
  （若会发生，说明那是采样不足，本仪器把两类搞混了——`pr:two-failures` 的整个要点就是不许混。）
- 最小实验：拿 `ledger/triggers/` 与 `thinking/blind_spots.md` 的判例，
  对每条 `bs_guard` 问一句"看住它的那条检查，观测域看得见这条判例描述的缺陷吗"。
- 对照：对一条确属采样不足的判例（BS-009 单次证据冒充分布）应当**判为满秩**。
- 服务：`ch09` 方向三的否证条件（"监视器可观测的事件不足以判定关键性质"）。

### T6 `assay attest` — 佐证与 `q` 的估计 **（`th:correlated`、`cor:diversity`、H8/H11、O4）**

- 可观察后果：每条软声明的佐证条数、佐证者之间的**历史错误相关系数**、由此得到的 `q` 估计。
- 会否证它：异质佐证组相对同质佐证组的多数错误率**没有显著差异**（即 `q` 本来就小，H8 的否证条件）。
- 最小实验：`H11` 已给出三种配置（少而无激励 / 多而无激励 / 少而有评分规则）——
  本仓有 32 条 `D` 与 47 条 `O` 可作为候选语料，先只做**回顾性**相关系数。
- 对照：多而无激励 vs 少而有评分规则；若前者不劣于后者，则"加人"确有独立价值。
- 服务：O4（论文称"这是该方向能否落地的关键"）、H8、H11。
- **边界**：引擎**不判断谁对**（`PROTOCOL.md` §7）。本仪器只报相关系数与 `n_eff`；
  后果由人承担。

### T7 `assay bind` — 第四根柱子 **（`eq:binding`、`pr:reproducible`、H9）**

- 可观察后果：构建非确定性比例、部署漂移事件率、以及**部署期假设复查**的失败率。
- 会否证它：该缺口在真实部署中**不可测量**，或补齐成本远超收益（H9 的否证条件）。
- 最小实验：在本仓 CI 里让一条证据束绑定到产物摘要，再故意改一个字节，要求部署期复查转红。
- 对照：只做可复现构建、不做密码学绑定的对照组，应当**测不到漂移**（说明绑定确有增量）。
- 服务：H9、`pr:reproducible`。

### T10 `assay transport` — 运输前提生成器 **（`prop:transport` 4.15、`cor:transport-test` 4.16、`def:fibration` 4.14）**

论文给出了采纳外部实现时的**逐槽判据**，而且给了判别器：

> 若问题形状之间的映射是**等价**的（资源形态、并发结构、失效模式、时间尺度四项相同），
> 则 𝓚₆ 的**槽位**（每个职能必须回答的问题）在运输下保持；实现形态可改，槽位不增不减。
> 若映射不是等价，则至少一个槽位的语义要求改变，**必须重新推导**。
> 判别器：**"同一槽位在不同基座上的实现差异"不是反例；"槽位本身的差异"才是反例。**

- 可观察后果：把一个外部结果（内核细化定理、宿主机运行时契约、库定理）对应到本项目的六个槽位时，
  每一项是"同槽异实现"还是"槽位不同"；判为后者的槽位必须重新推导。
- 会否证它：被它判为"同槽"的运输，在实际接入后出现**语义要求改变**的槽位。
- 最小实验：层表 `[level.k6]` 里凡 `bearer = "adopted:..."` 的格子，逐格填四项形状并比对。
- 对照：把一个**明知不同槽**的移植（如把帧驱动调度器的结论搬到事件驱动调度器）喂进去，应当判为"槽位不同"。
- 服务：`cor:buildadopt`、§5.2。
- **边界**：论文自陈 `def:fibration` "是**结构性提案**，不是范畴论既有定理的应用"，
  把 π 提升为严格纤维化并证明重指数函子性质**是未完成的工作**（`rmk:fibration-status`）。
  所以本仪器只做**逐槽比对表**，不声称任何函子性。

## 5. 外部形式化工具如何进场（本节回答"TLA+ / Lean / L4 怎么都用得上"）

**先纠正一处事实**：论文正文点名 seL4（`ex:sel4-cost`，成本范例）与 Lean（`H7` 的基准证据，
`verina2026`）；TLA+ 只出现在参考文献里；L4 微内核谱系、CompCert、Coq、Isabelle、Dafny、Z3
在 `docs/paper/en/` 全目录**零命中**。所以问题不是"论文说了要用它们"，
而是"**框架蕴含了哪一类义务只有它们能兑现**"。

`PROTOCOL.md` §3.1 已经规定了从便宜到贵的顺序，并写下"**买工具必须指向一个饿着的义务**"。
缺的不是顺序表，是**哪类义务喂哪张嘴**。四类：

| 义务类别 | 出处 | 为什么更便宜的手段给不了 | 因此买进 |
|---|---|---|---|
| **协议良型性与不动点** | `prop:operad-compose`(b)、`rmk:feedback` | 环上的存在性/唯一性不是有限状态搜索能给的；TLC 需要在有限模型上、且要写公平性 | TLA+ / Quint（本仓已用：`tla/queue.tla`、O-044） |
| **层间伴随与语义保持（全称形式）** | `def:galois` 的 `α(b) ⊑ b' ⟺ b ⊑ γ(b')`、`prop:soundness` 的 (a)(b) | 既不是有限状态搜索，也不是一阶契约——它是关于**行为集合**的全称命题，带归纳结构 | **Lean**（见下） |
| **L1 的一份被采纳的无视集** | `th:six` + `cor:buildadopt` + `def:oblivious` | 六职能不可省略，只能自建或采纳；采纳的是**别人算好的商** | **seL4 / L4 类微内核**（见下） |
| **不可满足性与证书** | `ch11` R10 的替代方案（Farkas 证书 / UNSAT 核心）；`ch09` 阶段 3 的 "controlled decidability" | 需要**可独立复核的不可行性证明**，而不是超时 | SMT/LP 的证书路径 |

### 5.1 Lean 的合法入口：层间伴随义务

`def:galois` 说：**"凡层间关系能写成 Galois 连接，语义保持条件就变成机械可判的。"**
这句话是有价格的——价格就是**证明那个伴随**。它的形态（对全部 `b ∈ 𝓑_{i+1}`、`b' ∈ 𝓑_i`
的全称等价，带单调性与伴随律）不属于任何有限搜索，也不属于任何一阶契约。
这是本文能找出的、框架内**唯一**一块天然属于证明助手的义务。

于是 Lean 的进场规则可以写死：

> **只有在你确实需要"层间语义保持可机械判定"时，才欠下伴随义务；欠下伴随义务时，Lean 才饿。**
> 不声明 Galois 连接的层对，不欠这条义务，也不需要 Lean——它们回到 `prop:soundness` 的
> 充分条件清单，或回到模拟关系与显式人工论证（`def:galois` 原文就这么说）。

这与本仓既有判断**完全一致**：`thinking/blind_spots.md:50` 记着
"Lean 被否（无 C/C++/Rust 自动验证器，**无饿着的义务**）；TLA+ 被采纳（O-016/O-017 恰好饿着 liveness 证据）"。
**那次否决是对的。** 本文要加的不是"该用 Lean 了"，而是一条**让 Lean 在正确时刻变饿的接口**。

同时必须挂上论文自己的价签与瓶颈：

- `ex:sel4-cost`：11 人年、约 20 万行证明脚本、8,500 行 C。
- `pr:two-costs`：检查时间便宜，**证书长度不便宜**，"没人能读完的证书在工程上不可用"。
  → 所以买证明助手时必须**同时预算可读摘要层**（不变量、契约的散文陈述、反例），
  并把证书长度当作一等证据字段（见 §6 的 S5）。

### 5.2 seL4 / L4 的合法入口：一份被采纳的无视集

这是本文最愿意主张的一条 **[X]**：

> **一个微内核，卖的是一份被采纳的无视集。**
> `def:oblivious` 说抽象就是按核取商。L1 的 `ker α` 正是"调度怎么选、内存怎么分、
> 故障怎么隔、名字怎么解"这些差异。自建 L1 是自己算这个商（付 `th:integration` 的摊销不等式）；
> 采纳 seL4 是**买别人算好的商**，并且这个商附带一份细化证明。

于是：

- `cor:buildadopt` 给出的不是"该不该自建"，而是一条**可判定的分界**：
  不变式若是**领域关键**的（"只能在本系统自己拥有的保证下成立"）⇒ 必须自建；
  若是**通用**的（"通用宿主机能提供足够强度的保证"）⇒ 应当采纳；
  自建一个通用职能 = 论文点名的"**商品件的重复发明**"。
  论文的总结句是："**你被迫拥有的那组不变式，就是你的内核的边界。**"
- 因此层表的 L1 行 `[level.k6]` 六格里每一个 `bearer = "adopted:..."`，
  都是在回答"这份商买得对不对"，而**分界由不变式的领域关键性给出，不由偏好给出**（`cor:buildadopt`）；
- 采纳一份细化定理要付**运输前提**（`prop:transport`、`def:fibration`），
  逐槽判据与判别器见 T10；这些前提是 `trust_assumption` 的**合法去处**：
  不是散文，是带 ID、带承担者、带否证条件的边；
- 第四根柱子（`eq:binding`）把 `verified image` 钉到 `booted image`——
  **这正好是 L4 类内核"能力 + 隔离"所覆盖的那一档**（`ch07` Table `tab:effects` 的 security 行）；
- **诚实边界**：采纳一个核只买到它覆盖的那些槽位（主要是 F6 隔离/恢复，以及 F2、F3、F4 的一部分），
  且只买到**在相同问题形状下**的槽位（`prop:transport`）。它不给你 L2/L3 的正确性，
  也不给"规格符合意图"。这正是论文 `Q8` 的立场：**不建立统一形式化，只建立共享证明接口与证据格式。**
  本文同样不建立。

### 5.3 三类工具并列时的纪律

`ch07` `rmk:three-prototypes` 已经点名：沙箱、字节码验证器、资源计量机制各自保证的东西
**不同，不得并列宣传**。同理：TLA+（协议层）、Lean（层间伴随）、内核（L1 执行边界）
三者判的是三件不同的事，把它们并排写成"我们都形式化验证过了"是这个框架明确禁止的读法。
层表的作用正是让这种并列**在结构上无法成立**：三者落在不同的行的不同的列上。
