# Spec Ledger 宪法（v0）

本仓库的治理文件。任何人或 AI 在本仓库工作前，必须先读这份文件，再读 `AGENTS.md`。
术语以 `thinking/glossary.md` 规范名表为准（一物一名，D-022）。

## 硬/软之分——按"声明"分，不按"文件"分

同一条声明，写成机器可检查的形式就是硬的，写成自由文本就是软的。载体不决定硬度，
决定的是两件事：**违反时谁会发现**（CI 几分钟内，还是三个月后评审会上的人类记忆），
以及**结论的语义强度**（证明 / 证据 / 意见）。

- **A（硬）**：机器可检查的声明。必须有检查器，CI 强制。
- **A'（机器证据）**：自动执行但结论不可靠的证据（压力测试、bench、fuzz）。同样必须登记并运行。
- **非A（软）**：需人判断的声明（意图、取舍、审美）。必须有 owner 签名，
  且必须回答"什么证据会推翻我"。
- **中间地带非法**：既不机器检查、又无签名的约束性散文，禁止入账。

## 三律（由 `tools/ledger_lint.py` 强制）

1. **硬声明交检查器**（L2）——没有检查器的形式化是装饰。
2. **软声明交签名**——rationale / 豁免 / 延迟证据必须有 anchor 或 owner；无主的判断会腐化。
3. **每个产物有主，每个目标有验收**（L1 / L3）。

## 记账规则

```text
L1  ∀ artifact   ∃ decision        没有无主的代码
L2  ∀ obligation ∃ checker ∧ PASS  没有裸奔的义务（deferred 需 reason+owner → WARN）
L3  ∀ goal       ∃ evidence        没有无人验收的目标
```

## 增长律

每条软声明都要回答"什么证据会推翻你"。有答案的，进入迁入 A 的队列。

检查器阶梯（由弱到强）：

```text
lint/约定 → 架构测试 → 类型/契约 → 压力/性质测试 → 模型检查 → 机器证明
```

同一义务的证据强度应随时间升级；升级历史留在 evidence 里。

## 账本瘦身

义务被反复满足后，可下沉为类型或运行时强制，然后从账本注销。
账本自身也接受被推翻：四周后按 `experiments/protocol.md` 的退出条款裁剪或关停，是合法结局。
