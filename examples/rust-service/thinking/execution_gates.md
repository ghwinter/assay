# 执行循环的强制门（Agent/AI 生成代码时的强制思考清单）

适用：Agent 执行循环——生成代码 | 调用工具 | 命令 → 循环 → 产物。
架构原则：产物 = 纯净零运行时依赖代码；TLA+/Verus/Debugger/账本全部是
**代码外的脚手架**（开发期工具，永不进 Cargo.toml [dependencies]）。
本清单是循环里强制经过的门——每道门一组必答问题，答不出就停下。

---

## 门 0：装载（循环入口）
- 账本是否已装载（G/D/O/E + triggers）？thinking/ 盲区清单是否在评审视野？
- 本任务有 accepted 的 D 覆盖吗？没有 → 先起草（不得直接动 src/）

## 门 1：可验证性分诊（核心门——对每个设计元素逐一过）
问：**这个元素属于哪类声明，最便宜的足够证据是什么档？**
- 并发协议 / 状态时序 / 活性 → TLA+ 档（模型先于实现）
- 纯逻辑 / 不变量 / 前后置 → Verus 档（规约先于实现）
- 行为 / 边界 / 回归 → 测试档
- 竞争 → 语言强制（safe Rust）+ 按风险升级 loom/TSAN
- 运行时性能 → bench 档（阈值必须带锚点，BS-001）
- 仅可观测（不可验证）→ **降级路径**：代码 + 注释标记
  `[unverified: 原因]` + debugger 验收脚本 + 人工验收点
- 验证本身的时间/空间成本（证明工时、状态空间爆炸）计入"可接受"判断；
  超预算 → 降级路径，义务保留、证据标 deferred+owner

## 门 2：零依赖纯度
- 本次变更新增 [dependencies] 了吗？新增 = 需要 accepted D（0 运行时依赖是 G 级目标）
- 脚手架（tla/ proofs/ tools/ dev-deps）是否全部位于产物之外？

## 门 3：生成期诚实
- 每个"我记得"的 API/事实，有运行证据吗？（BS-011：Bag 算子教训——编译/运行即查证）
- 规约完整刻画结果了吗？（cap 条款教训：字段等式与保持条款不可漏）
- rationale 有锚点吗？（BS-006：不得为既有意图补造理由）

## 门 4：验证路由（阶梯）
- 每条义务的 checker 实际运行了吗？（没有裸奔的义务——L2）
- 失败 = 红灯 = 提交被阻；三条合法响应（改代码 / 带锚点改决策 / 撤回无锚点阈值）

## 门 5：降级路径验收（不可验证部分的出口）
- debugger 脚本（崩溃证据/路径快照）跑过并入账了吗？
- `[unverified]` 标记的清单是否随附人工验收点与 owner？

## 门 6：元认知对照（宣告完成之前）
- 对照 blind_spots 全表：本轮是否中了任何一条？（逐条 30 秒）
- 预测先于结果了吗（M-009）？异体对照可用吗（M-010）？

## 门 7：入账与提交
- lint 绿 + 测试过 = 完成定义；Conventional Commits；
- 本轮若冒出账本未预见的推理错误/事故 → 判例回写 thinking/（M-008）

## 示例：构建 web 框架（react-rust 类）的分诊结果

| 框架组件 | 分诊 | 脚手架 |
|---|---|---|
| 路由表匹配（纯函数） | Verus 档 | proofs/routing.rs |
| 连接状态机 / keep-alive / 背压协议 | TLA+ 档 | tla/conn.tla |
| HTTP 解析器 | 测试档 + fuzz（输入空间大） | tests/ |
| 中间件组合语义 | 测试 + 类型系统 | tests/ |
| async 调度核心 | TLA+（协议）+ Verus（核心数据结构）+ 语言强制 | tla/ proofs/ |
| 性能预算 | bench 档（阈值带锚点） | benches/ |
| 进程崩溃取证 | 降级路径：debugger 证据 | tools/debug/ |
